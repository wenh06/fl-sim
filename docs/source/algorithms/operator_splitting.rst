Operator Splitting Algorithms in Federated Learning
---------------------------------------------------

.. _fl_alg_os_correctness:

Why operator splitting? The correctness of the limit
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Most existing federated learning algorithms deal with the convergence rate and stability in
non-I.I.D. scenarios, while the *correctness* of the point they converge to has long been
overlooked. A simple least-squares example shows that the limits of ``FedAvg`` and ``FedProx``
generally differ from the true solution of the federated problem
[:footcite:ct:`pathak2020fedsplit`].

Consider fitting a linear model :math:`y = mx` (with :math:`m` the unknown) by least squares,
with two clients: client 1 holds the data :math:`\{(0, 2), (1, 2)\}`, hence

.. math::

   f_1(m_1) = \frac{1}{2} \left( 4 + (m_1 - 2)^2 \right);

client 2 holds the data :math:`\{(2, 0), (2, 1)\}`, hence

.. math::

   f_2(m_2) = \frac{1}{2} \left( 4 m_2^2 + (2 m_2 - 1)^2 \right).

Fitting on each client separately yields :math:`m_1 = 2` and :math:`m_2 = \frac{1}{4}`;
``FedAvg`` returns the average :math:`m = \frac{9}{8}`, while ``FedProx`` (minimizing the objective
with the proximal term) returns

.. math::
   :label: eg-correctness-fedprox

   m = \frac{18 + 4\mu}{16 + 9\mu},

where :math:`\mu` is the proximal coefficient. However, fitting all the data jointly gives
:math:`m = \frac{4}{9}`. The discrepancy arises because the objective is quadratic in :math:`m`:
the average of the individually fitted models generally differs from the jointly fitted model.

More generally, [:footcite:ct:`pathak2020fedsplit`] analyzed the limit points of ``FedAvg`` (in its
simplified full-gradient form, termed ``FedGD``) and ``FedProx``: assuming each :math:`f_k` is
convex and :math:`L`-smooth, and that the sequences generated by the algorithm converge, then all
clients share a common limit :math:`\theta^*` characterized by the fixed-point conditions

.. math::
   :label: fedgd-fixed-pt

   \sum\limits_{i=1}^R \sum\limits_{k=1}^K \nabla f_k\big( \mathcal{G}_k^{i-1}(\theta^*) \big) = 0,
   \qquad
   \mathcal{G}_k(\theta_k) := \theta_k - \eta \nabla f_k(\theta_k),

for ``FedGD`` (:math:`R` being the number of local steps), and

.. math::
   :label: fedprox-fixed-pt

   \sum\limits_{k=1}^K \nabla \mathcal{M}_{f_k, \mu}(\theta^*) = 0, \qquad
   \mathcal{M}_{f_k, \mu}(\theta) := \inf_{\theta_k} \left\{ f_k(\theta_k) + \frac{\mu}{2} \lVert \theta - \theta_k \rVert^2 \right\},

for ``FedProx``, where :math:`\mathcal{M}_{f_k, \mu}` is the Moreau envelope of :math:`f_k`.
Applied to a least-squares problem :math:`f_k(\theta_k) = \frac{1}{2} \lVert A_k \theta_k + b_k \rVert^2`
(with :math:`A_k` of full column rank), these fixed points admit closed forms that generally differ
from the true solution :math:`\theta^* = \big( \sum_{k=1}^K A_k^{\mathrm{T}} A_k \big)^{-1} \sum_{k=1}^K A_k^{\mathrm{T}} b_k`
of the joint problem.

This observation motivates reformulating the federated problem in a form whose splitting-based
solution converges to the *correct* point, which is exactly the route taken by ``FedSplit`` and
``FedDR`` below.
