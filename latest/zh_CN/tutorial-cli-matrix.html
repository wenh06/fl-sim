教程：用 CLI 跑实验矩阵#

随着实验数量增长，为每个实验单独编写 Python 脚本将变得难以管理。fl-sim 命令行接口能用单个 YAML 文件运行一整个 实验矩阵 ：配置网格只需描述一次，CLI 负责展开并执行每个组合。本教程在合成数据上构建一个四次运行的矩阵，并展示结果的写入位置。

YAML 语法参考见 命令行接口 ；本页讲的是工作流程。前置阅读：教程：第一个对照实验 。

矩阵文件#

本教程的完整配置如下（example-configs/fedsynthetic-demo.yml ）：

# Demo config for the CLI tutorial: a 4-run experiment matrix on
# synthetic data. Every combination of `clients_sample_ratio` and `seed`
# in `strategy.matrix` is run once. Runs in seconds, no downloads.

strategy:
  matrix:
    clients_sample_ratio:
    - 0.5
    - 1.0
    seed:
    - 0
    - 1
  n_parallel: 1  # number of parallel jobs, not supported yet but kept for future use

algorithm:
  name: FedAvg
  server:
    num_clients: 30
    clients_sample_ratio: ${{ matrix.clients_sample_ratio }}
    num_iters: 3
    log_dir: fedsynthetic-demo
    # a distinct tag per matrix combination: log file names carry the
    # tag, so runs finishing within the same minute never overwrite
    # each other's json/txt logs
    tag: ratio_${{ matrix.clients_sample_ratio }}_seed_${{ matrix.seed }}
  client:
    num_epochs: 1
    batch_size: 32

dataset:
  name: FedSynthetic  # synthetic data: no download, seconds per run
  alpha: 1.0
  beta: 1.0
  iid: true
  num_clients: 30

model:
  name: mlp_d1

seed: ${{ matrix.seed }}

三个关键部分：

  • strategy.matrix——网格。列出的值每个组合各跑一次：2 个采样比例 × 2 个种子= 4 个实验。

  • ${{ matrix.<key> }}——插值。该模式出现之处，CLI 都会代入当前组合的值。seed 位于顶层，因此它同时为该次运行的数据集 和 服务器配置设定种子。

  • 其余部分—— algorithm （名字加服务器/客户端配置）、 dataset 、 model ——与你在 Python 里传入的配置（见 快速上手 ）完全一致，只是改写成 YAML。数据集各自的构造参数（ FedSynthetic 的 alpha 、 beta 、 iid 、 num_clients ）原样透传。

运行矩阵#

fl-sim example-configs/fedsynthetic-demo.yml

四次运行依次执行，各自记录自己的组合（ ratio=0.5 seed=0 等）。总耗时数秒，无下载。

结果位置#

所有运行都写入 ~/.cache/fl-sim/.logs/fedsynthetic-demo/``（本配置的 ``log_dir ）。每次运行各有一份 .txt 与一份 .json 日志——即 快速上手 描述过的那些文件——另有一份 config.json 保存最近一次运行的确切服务器/客户端配置（已有的 config.json 会被轮转为 config.json.bak ）。

当多次运行在同一分钟内结束时，一个细节便变得重要：日志文件名带有时间戳 以及该运行的 ``tag`` 。若每个矩阵组合没有独特的 tag，同名的日志会互相覆盖。上面配置中的 tag: ratio_${{ ... }}_seed_${{ ... }} 一行正是为此：每个矩阵分支都有自己的 tag。

超越串行执行#

由长时间实验组成的矩阵需要不止一个进程。 strategy 节还接受并行选项（ n_parallel，或 parallel: {mode: parallel_task, num_workers: N} 块），把矩阵分支派发给工作进程——完整示例见 example-configs/multiprocessing-demo.yml；进程内把 单次运行 的客户端并行化的执行器后端见 Parallel execution layer 。两者正交：进程级并行作用于矩阵分支之间，执行器级并行作用于客户端之间。
